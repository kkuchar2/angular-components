1. Paginated + column chips + cellComponent

Same features as Material app-generic-table: chip column toggle, client-side pagination, sorting, export, built-in uuid/date cells with optional copy, plus reusable cellComponent cells (status badge). Pass [rowActions] for a rightmost ⋮ context menu (app-context-menu). Projected templates still work for one-offs. Columns with searchable: true open a text field in the left filter rail; toggleable: true lists unique values as checkboxes. Text and toggle filters combine with AND.

@if (selectedRow(); as row) {

Selected: {{ row.name }} ({{ row.email }})

} @if (lastRowAction(); as action) {

Last row action: {{ action }}

}

2. Scrollable column filters

Searchable columns show a text field; toggleable columns list unique values as checkboxes. With filterMinHeight, the rail keeps its own height and scrolls when filters overflow. Text + toggles AND together; multiple checks within a column OR.

3. Row details menu

Same ⋮ trigger with rowMenuVariant="details" — opens a larger panel of read-only fields via [rowDetails] / [rowDetailsTitle] instead of action items.

4. Cell component catalog

Reusable library cells via ColumnDef.cellComponent: PersonCellComponent, MailtoCellComponent, StatusBadgeCellComponent, and BooleanCellComponent.

5. Animated cells

Motion-friendly cells (respect prefers-reduced-motion): pulsing presence, grow-in progress bars, and trend deltas.

6. Server-side pagination

Parent owns the page slice. Export waits for exportRequest.complete().

7. Virtual scroll (10 000 rows)

TanStack Virtual — person + status cells stay cheap enough for large lists. Mutually exclusive with pagination.

8. Empty state

Non-virtual table with no rows.

9. Parent height mode

heightMode="parent" fills a flex: 1 parent, even when rows are fewer than the space. height is a floor; maxHeight is a cap.

flex: 1 parent (40rem), maxHeight="360px"
flex: 1 parent (8rem), height="240px"
