1. Paginated + toolbar + filters

The toolbar has two fixed slots. Leading holds the filter affordance (plus a Clear button once something is active); trailing holds the tools — anything you project with gttTool, then Columns, then Export. They are anchored to opposite edges, so no combination of options can make them collide or swap places. Below 34rem the controls drop their labels rather than wrapping, so the toolbar is exactly one row tall at every width.

Columns with searchable: true get a text field in the filter rail; toggleable: true lists their values as checkboxes. Text and toggles combine with AND, multiple checks within a group with OR. Toggle a Status and watch the Department counts narrow — options that fall to 0 stay in place but disabled, so the list never jumps.

2. Responsive behaviour — drag to resize

Grab the bottom-right corner. Three things change, each at its own threshold and none of them changing the table's height:

  • 720px — the filter rail costs more than it returns, so it is replaced by a modal with draft state: closing discards, Apply commits. The Filters button itself never moves.
  • 34rem — toolbar controls and the paginator's Rows per page label collapse to icons.
  • 26rem / 17rem — the paginator drops its first/last buttons, then its range label. It sheds controls instead of wrapping, so it stays 2.75rem tall throughout.

3. Filter rail height

In auto height mode the rail is capped by filterMaxHeight (default 26rem) and scrolls past it, so a long filter list can't stretch a short table. In fill and parent modes the rail simply matches the table and the cap is ignored.

4. Column visibility: menu vs. chips

columnToggle="menu" (the default) keeps a constant footprint no matter how many columns there are. columnToggle="chips" renders a full-width band below the toolbar so the chips can wrap freely without ever pushing the tools around. Neither mode lets you hide the last visible column.

5. Row details menu

Same ⋮ trigger with rowMenuVariant="details" — opens a larger panel of read-only fields via [rowDetails] / [rowDetailsTitle] instead of action items.

6. Cell component catalog

Reusable library cells via ColumnDef.cellComponent: PersonCellComponent, MailtoCellComponent, StatusBadgeCellComponent, and BooleanCellComponent.

7. Animated cells

Motion-friendly cells (respect prefers-reduced-motion): pulsing presence, grow-in progress bars, and trend deltas.

8. Server-side pagination

The parent owns the page slice. With serverSide the table also stops sorting locally — it emits sortChange and leaves the row order alone — and export waits for exportRequest.complete(). Filter edits are published through filtersChange.

9. Virtual scroll (10 000 rows)

TanStack Virtual, with the header stickied inside the same scroll container as the rows — so it tracks horizontal scrolling for free. Mutually exclusive with pagination.

10. Horizontal overflow

Column tracks resolve to minmax(minWidth, width), and the grid is min-width: min-content — the sum of those floors. Wider than the container and it scrolls sideways under a pinned header; narrower and the flexible columns absorb the slack. No width measurement in JavaScript.

11. Empty states

No rows at all shows emptyMessage. Rows filtered down to nothing shows a different message plus a one-click escape hatch.

12. Height modes

In auto, height/minHeight/maxHeight size the scroll shell (header + rows). In fill and parent the parent's box governs instead: height becomes the whole table's floor and maxHeight its cap.
